# Data Manager Cloud Integration Specification (`DATA_MANAGER_SPEC.md`)

This document defines the exact interface contract between the **I/O Manager (`TelegramIOManager` / `main.py`)** and the **Data Manager (`DataManager` / `SupabaseHandler`)**.

Right now, `TelegramIOManager` runs in **Cloud Stub (In-Memory) Mode** (`use_cloud=False`) because `DataManager.CLOUD_READY` is not yet set to `True`. Once the Data Manager implements the methods below and sets `CLOUD_READY = True` on `DataManager`, the entire Telegram bot and screening pipeline will automatically switch to live Supabase Cloud storage with **zero edits needed in `io_manager_modules/`**.

---

## 1. Architecture & Handshake Overview

1. **No Local Company Files:** The app runs as a headless Telegram Server (`python main.py`). Users interact exclusively through Telegram. Do **not** depend on local `companies/` folders or `companies.json`.
2. **Automatic Switch-Over Flag:**
   Add `CLOUD_READY = True` as a class attribute on `DataManager` (`data_manager_modules/data_manager_side.py`) once all methods below are implemented.
   - `main.py` and `TelegramIOManager` check `getattr(data_mgr, "CLOUD_READY", False)`.
   - When `False` (default right now), `TelegramIOManager` uses its in-memory stub stores.
   - When `True`, `TelegramIOManager` calls the `DataManager` methods listed in Section 3.

---

## 2. Recommended Supabase Schema & Storage Structure

### Storage Bucket (`resume_files` or `resumes`)
- **Path format:** Store each PDF under `<company_id>/<file_name>` (e.g., `101/john_cv.pdf`), **not** at the bucket root. This prevents two companies from overwriting each other's files with the same filename.
- **Empty company folder placeholder (optional):** Upload `b""` to `<company_id>/.keep` inside `create_company()` if you want the folder visible in Supabase Storage immediately before any PDFs are uploaded.

### Database Tables (PostgreSQL / Supabase SQL)

```sql
-- 1. Companies table (fixes foreign key error fk_resumes_company)
CREATE TABLE IF NOT EXISTS companies (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    company_name TEXT UNIQUE NOT NULL,
    invite_code TEXT UNIQUE NOT NULL,
    passcode_hash TEXT NOT NULL,
    owner_id BIGINT NOT NULL,
    members JSONB NOT NULL DEFAULT '[]'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 2. Business Rules per company
CREATE TABLE IF NOT EXISTS business_rules (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    company_id BIGINT NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
    rules JSONB NOT NULL DEFAULT '[]'::jsonb,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (company_id)
);

-- 3. Resume Files (scoped by company_id + file_name)
-- Note: Ensure the unique constraint is on (company_id, file_name), NOT just file_name globally.
ALTER TABLE resume_files
    ADD COLUMN IF NOT EXISTS company_id BIGINT REFERENCES companies(id) ON DELETE CASCADE;

-- Drop old global file_name unique constraint if present, and add per-company unique constraint:
-- ALTER TABLE resume_files DROP CONSTRAINT IF EXISTS resume_files_file_name_key;
-- ALTER TABLE resume_files ADD CONSTRAINT uq_resume_company_file UNIQUE (company_id, file_name);

-- 4. Filtered Resumes (Accepted / Rejected / Invalid), Ranked Candidates & AI Summary per company
CREATE TABLE IF NOT EXISTS filtered_resumes (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    company_id BIGINT NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
    accepted JSONB NOT NULL DEFAULT '[]'::jsonb,
    rejected JSONB NOT NULL DEFAULT '[]'::jsonb,
    invalid JSONB NOT NULL DEFAULT '[]'::jsonb,
    ranked_candidates JSONB NOT NULL DEFAULT '[]'::jsonb,
    summary_data JSONB,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (company_id)
);
```

*(Ensure RLS policies allow `SELECT`, `INSERT`, `UPDATE`, `DELETE` for the project's Supabase key on both Storage and the tables above.)*

## 3. Required `DataManager` Methods & Return Formats

Implement these methods on `DataManager` in `data_manager_modules/data_manager_side.py` (backed by `SupabaseHandler` in `data_manager_modules/data_manager_supabase_handler.py`):

```python
class DataManager:
    CLOUD_READY = True  # Set to True once Supabase methods below are implemented
```

### A. Company Management

#### 1. `create_company(self, company_name: str, passcode_hash: str, owner_id: int, invite_code: str) -> Dict[str, Any]`
Inserts a new row into Supabase `companies` (and optionally creates `<company_id>/.keep` in Storage).
- **Raises:** `ValueError` if `company_name` already exists.
- **Returns:**
  ```python
  {
      "company_id": 1,                  # int (Supabase row id)
      "company_name": "Acme Corp",      # str
      "invite_code": "ACME-4821",       # str
      "passcode_hash": "<sha256_hex>",  # str
      "owner": 123456789,               # int (owner_id)
      "members": [123456789],           # list[int]
  }
  ```

#### 2. `get_company_by_invite(self, invite_code: str) -> Optional[Dict[str, Any]]`
Looks up a company by case-insensitive `invite_code`.
- **Returns:** Same dictionary format as `create_company`, or `None` if not found.

#### 3. `add_company_member(self, company_id: int, user_id: int) -> None`
Appends `user_id` to the company's `members` list in Supabase if not already present.

---

### B. Business Rules Management

#### 4. `get_company_rules(self, company_id: int) -> List[Dict[str, Any]]`
Fetches the saved rules list for `company_id` from `business_rules`.
- **Returns:** List of rule dicts (or `[]` if none):
  ```python
  [
      {"text": "Minimum 3 years Python experience", "priority": "must"},
      {"text": "Experience with Docker", "priority": "important"},
  ]
  ```
  Valid `priority` strings: `"must"`, `"important"`, `"nice"`, `"can consider"`, `"reject"`.

#### 5. `save_company_rules(self, company_id: int, rules: List[Dict[str, Any]]) -> None`
Upserts the full `rules` JSON array for `company_id` in `business_rules`.

---

### C. Resume Upload, Listing, Download & Deletion

#### 6. `upload_resume_bytes(self, file_name: str, pdf_bytes: bytes, company_id: Optional[int] = None) -> Dict[str, Any]`
*(Already exists — update it for multi-company safety)*
1. Parses `pdf_bytes` with `self.parse_pdf_bytes(file_name, pdf_bytes)`.
2. Uploads to Storage at path `f"{company_id}/{file_name}"` (so companies never overwrite each other).
3. Upserts into `resume_files` with `on_conflict="company_id,file_name"`.
- **Returns:**
  ```python
  {
      "file": "john_cv.pdf",
      "file_name": "john_cv.pdf",
      "status": "valid",          # "valid" or "invalid"
      "reason": "",               # empty if valid, error string if invalid
      "pages": 2,
      "text": "<extracted text>",
      "pdf_url": "https://...",
      "company_id": 1,
      "source": "Supabase Cloud",
  }
  ```

#### 7. `list_company_resumes(self, company_id: int) -> List[Dict[str, Any]]`
Queries `resume_files` where `company_id == company_id`.
- **Returns:** List of dicts with keys:
  `"file"`, `"file_name"`, `"status"`, `"reason"`, `"pages"`, `"text"`, `"pdf_url"`, `"source"` (`"Supabase Cloud"`).

#### 8. `download_resume_bytes(self, company_id: int, file_name: str) -> Optional[bytes]`
Downloads the raw PDF bytes from Supabase Storage path `f"{company_id}/{file_name}"` (or `None` if missing) so the Telegram bot can send the PDF directly to the user.

#### 9. `delete_company_resume(self, company_id: int, file_name: str) -> bool`
Deletes the file from Storage (`f"{company_id}/{file_name}"`) and its row in `resume_files`. Returns `True` if deleted, `False` otherwise.

#### 10. `clear_company_resumes(self, company_id: int) -> None`
Deletes all resumes for `company_id` from Storage and `resume_files`.

---

### D. Filtered Resumes, Screening Results & AI Summary Persistence

#### 11. `save_screening_results(self, company_id: int, ranked_candidates: List[Dict[str, Any]], summary_data: Optional[Dict[str, Any]], filtered_resumes: Optional[Dict[str, Any]] = None) -> None`
Upserts `ranked_candidates`, `summary_data`, and `filtered_resumes` (`{"accepted": [...], "rejected": [...], "invalid": [...]}`) into the `filtered_resumes` table in Supabase for `company_id`.

*(Note: `main.py` also calls `outputfile_func(accepted, rejected, invalid, output_folder, company_id=company_id)` if `outputfile_func` accepts `company_id`—you can optionally persist `accepted`, `rejected`, `invalid` to Supabase inside `outputfile_func` as well, or handle it in `save_screening_results`.)*

#### 12. `get_screening_results(self, company_id: int) -> Tuple[List[Dict[str, Any]], Optional[Dict[str, Any]]]`
Fetches `(ranked_candidates, summary_data)` from `filtered_resumes` for `company_id`, returning `([], None)` if not found.

## 5. Adding Future Data Types / Tables (2-Step Extensibility Pattern)

Whenever your team wants to store something new in Supabase (e.g., job postings, interview schedules, audit logs, or candidate notes):

1. **Data Manager side (`data_manager_side.py` & `data_manager_supabase_handler.py`):**
   - Create the new Supabase table with `company_id BIGINT NOT NULL REFERENCES companies(id) ON DELETE CASCADE`.
   - Add two clean methods on `DataManager` (e.g., `save_<feature>(self, company_id: int, data: ...)` and `get_<feature>(self, company_id: int)`).
2. **I/O Manager side (`io_manager_telegram.py`):**
   - Add a matching `_dm_save_<feature>` / `_dm_get_<feature>` bridge method that checks `if self._use_cloud and hasattr(self._data_manager, "...")` with an in-memory stub dictionary fallback, then wire a button in `TelegramKeyboards`.
